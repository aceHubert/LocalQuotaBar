# 执行计划使用说明

执行计划用于超出单轮聊天上下文、需要多次推进或风险较高的任务。

## 什么时候创建计划

- 任务会跨多个提交或多轮工作推进。
- 改动影响架构、数据协议、缓存迁移或其他高风险区域。
- 完成任务依赖阶段性验证、回滚策略或关键决策留痕。
- 多位贡献者或多个 Agent 需要持续协作。

## 存放位置

- 进行中的计划：[exec-plans/active/](exec-plans/active/)。
- 已完成的计划：[exec-plans/completed/](exec-plans/completed/)。
- 复用模板：[execution-plan.md](exec-plans/templates/execution-plan.md)。
- 明确推迟的债务：[tech-debt-tracker.md](exec-plans/tech-debt-tracker.md)。

计划文件使用简短的英文短横线名称，例如 `quota-cache-migration.md`；归档时保留文件名。

## 维护要求

- 写清目标、范围、背景、约束、风险和验证方式。
- 推进过程和关键决定记录在仓库中，不要只保留在聊天记录里。
- 状态变化时同步更新进度，说明阻塞点和下一步。
- 验证应与改动匹配：Swift 编译、提醒评估边界、菜单栏交互或真实设备通道；注明未验证项，不把计划中的检查写成已通过。
- 涉及缓存或持久化设置时，记录兼容策略和回滚方式。
- 完成后补齐验证结果并移至 `completed/`；取消或过期计划注明原因后归档，保证 `active/` 可信。
- 明确推迟的事项录入技术债表，关联计划并给出后续动作。

仅维护计划及模板无需额外历史记录；实际实现按 [历史记录规范](HISTORY_GUIDE.md) 留档。
