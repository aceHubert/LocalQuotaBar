# Z.AI 重置卡操作与持久幂等请求

- 状态：已完成
- 创建日期：2026-09-15
- 最后更新：2026-09-15

## 目标

在个人 Z.AI / BigModel Coding Plan 的 5h 和周重置卡旁提供重置按钮。同一账号、同一重置类型的未确认操作持续复用一个持久幂等键；仅 HTTP 200 且业务确认成功后清除。

## 范围

- 包含：两个重置入口、进行中/重试/已重置状态、按账号与类型隔离的持久请求键、成功后额度和卡片状态刷新、模拟网络及原生布局测试。
- 不包含：主动执行用户账号的真实重置、替用户消耗重置卡、团队套餐、Codex 重置、申请重置机会、抓取全量网络流量。

## 背景

- 已只读检查 ZCode 3.11.2 应用包：`useCodingPlanReset` 使用 `POST /api/v1/coding-plan/reset/use`，JSON 包含 `idempotency_key` 与 `reset_type`。
- 类型为 `FIVE_HOUR` 或 `WEEK`；认证为 ZCode JWT 与对应平台 OAuth，个人目标 `PERSONAL`。
- 当前项目仅查询 reset/status；现有卡片只支持展开。
- 用户明确要求失败重试一直复用 key，只有返回 200 才清除。HTTP 200 可能仍包含业务错误，因此还须确认成功码与 `data.used=true`。

## 风险

- 重复消耗：发请求前原子持久化 key；未知结果、非 200、业务失败、解析失败均保留；进行中禁用重复操作。
- 账号混用：使用稳定账号身份和渠道生成散列作用域，类型分别保存；点击时重新解析凭证与当前账号，不沿用旧界面的身份。
- 陈旧卡片：成功后暂时锁定操作，只有成功之后发起的新额度/卡片查询确认后才能开始下一次。
- 存储故障：读取损坏或写入失败时不擅自生成新请求，避免丢失重试身份；持久文件不包含令牌。
- 回滚：恢复本任务修改前快照，保留待确认请求文件，避免丢失幂等键。

- 网络注入模拟：请求参数、超时/HTTP/业务失败重试、重启复用、账号/类型隔离、成功清除、重复点击保护。
- 原生布局：298 点宽内每类卡片一行，按钮和展开动作独立，状态更新不重建卡片。
- 不通过真实接口验证成功，不消耗卡片；明确记录未覆盖场景。
